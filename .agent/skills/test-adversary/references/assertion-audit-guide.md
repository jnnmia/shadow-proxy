# 单元测试断言有效性审计指南 (Assertion Audit Guide)

在持续交付与红队审查中，测试套件「全绿」往往掩盖了极具欺骗性的**伪测试（Ghost Tests）**。本文档指导如何识别并消除测试中的假阳性。

---

## 一、假阳性典型特征

| 假阳性类型 | 代码特征 | 风险与危害 |
|---|---|---|
| **无断言测试** | 测试函数体内执行了若干调用，但完全无 `assert` 或 `self.assert*` | 代码只要不崩溃就报 PASS，业务逻辑完全失效时依然绿灯 |
| **恒真断言** | `assert True`, `self.assertTrue(True)` | 人为刷测试通过率或单测覆盖率，虚假安全感 |
| **平凡弱断言** | `self.assertIsNotNone(res)`, `assert len(res) >= 0` | 返回空列表或错误对象依然通过，未断言关键属性与值 |
| **空循环断言** | 在一个可能为空的 `for item in items:` 内部写断言，若 `items` 为空循环直接跳过 | 当生产代码返回空集（严重 Bug）时，测试静默通过 |
| **过度宽泛 Mock** | 对系统内层核心逻辑全量 Mock，Mock 返回预设假数据后断言该假数据 | 测试的只是 Mock 框架本身，未测任何真实业务行为 |

---

## 二、审计与加固动作

1. **静态扫描与门禁拦截**：
   - 借助 `adversary_runner.py audit-test` 批量扫描测试目录中的空断言与常数断言。
2. **断言必须可证伪**：
   - 每个测试用例在编写时，应该能够明确说出：“若我故意破坏代码的某一行，该测试会以哪一个断言失败”。
3. **空集合与异常断言守护**：
   - 在迭代校验列表前，先显式断言集合非空：`self.assertTrue(len(items) > 0)`。
   - 验证异常时，必须断言异常类型及错误信息关键词，避免意外的异常掩盖真实失败。
